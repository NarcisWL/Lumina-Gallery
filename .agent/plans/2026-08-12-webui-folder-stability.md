# WebUI 文件夹视图稳定性修复

## 目标

- 扫描或缩略图任务运行时，状态轮询不得对媒体表执行全库计数。
- 文件夹列表读取不得递归扫描后代目录、排序后代媒体或现场生成封面缩略图。
- 连续目录导航只保留一个轮询世代；请求卡住时必须超时，并保留上一份可用内容供用户重试。

## 实现契约

1. `library_stats` 由 SQLite 触发器随 `files` 写入增量维护，`/api/scan/status` 只读取单行快照。
2. `folders.cover_file_id` 与 `cover_last_modified` 仅在缩略图确认有效时写入；目录读取通过 `folders -> files -> thumbnails` 批量连接获取封面。
3. 删除、批量清理、来源移除、改名和清空缩略图时同步清理派生记录；仅当当前封面失效时执行后代候选重算。
4. 旧图库在后台任务协调器空闲时按 `rowid` 分批核验既有缩略图，保存游标并让出事件循环，不占用请求路径。
5. WebUI 使用单飞轮询器中断旧世代；API 请求统一为 15 秒截止时间。当前目录加载失败时保留旧内容，并显示重试入口。

## 验收

- `npm test`
- `npm run build`
- `git diff --check`
- 独立 Agent 复核 SQLite 迁移、删除/改名一致性、后台回填和 React 取消语义。

## 非目标

- 本任务不部署、不发布、不创建分支、不提交或推送。
- 本任务不改变媒体排序、用户路径权限或 API 响应字段。
