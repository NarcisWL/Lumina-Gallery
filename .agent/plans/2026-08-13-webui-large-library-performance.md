# WebUI 大媒体库性能与加载体验优化计划

## 目标

- 将媒体库首批请求从 500 条收敛为 120 条，并避免筛选请求为首包同步执行精确全量计数。
- 在首次进入和续页期间保持瀑布流与网格的稳定几何占位，避免缩略图边框密集闪现和内容填充引起的布局跳动。
- 在不引入新依赖、不改变现有 offset 分页兼容面的前提下，降低近百万媒体量级下的查询、图片解码和滚动采样压力。

## 实施边界

### 后端

- `/api/scan/results` 使用 `limit + 1` 判断 `hasMore`。
- 管理员无筛选全库读取 `library_stats` 精确总数；其它作用域返回带 `totalExact` 的已知下界，末页升级为精确值。
- 普通列表只对最终页项目查询收藏状态；收藏列表以 ID-only 收藏集合驱动，禁止恢复 path OR、`DISTINCT` 或热路径全量精确计数。
- 为默认日期、媒体类型、文件夹、文件大小与用户收藏分页建立幂等组合索引；媒体类型或文件夹叠加大小排序不得创建临时排序表。
- 受限账号系统状态不在首包并发执行四次权限范围精确计数；以显式精确性字段区分未知占位，且不得泄露全库统计。

### 前端

- 首批与续页统一按 120 条请求，媒体类型筛选下推服务端。
- 首次加载显示约两个视口的比例骨架；续页显示分列或整行骨架。
- 优先消费服务端缩略图宽高比；缺失时按媒体 ID 生成稳定比例，加载完成后不再按图片自然尺寸改变卡片高度。
- 首屏两行图片使用高优先级，其余图片异步懒加载；滚动采样使用 passive 监听与 `requestAnimationFrame`。
- 使用 `IntersectionObserver` 在约 1.5 个纵向视口前预取，并保证失败后分页锁可恢复。
- 只有当前数据集的媒体与目录首包完整成功后才能开放续页；初始加载、错误或数据集切换的 effect 前窗口必须拒绝预取。
- 查询缓存键包含媒体筛选；默认全库持久缓存绑定用户名、角色和授权路径指纹，权限变化时必须 miss。
- 初始骨架等待媒体与目录请求共同完成，旧位置目录项和空态不得覆盖新位置首载。

## 非目标

- 本轮不迁移到 keyset cursor，不改变现有 History/视口恢复协议。
- 本轮不实现瀑布流动态高度窗口化；长时间滚动后的 DOM 增长作为后续专项。
- 本轮不发布、不部署，也不访问或修改生产媒体库。

## 验收

- Node 20 后端与前端全套测试通过，Vite 生产构建通过，`git diff --check` 无错误。
- 百万行合成数据库验证默认、类型、目录、收藏首批查询及深页 offset；记录启动建索引与查询分位数。
- 本地合成媒体库在真实浏览器中验证首屏骨架、固定几何、图片淡入、提前续页和失败可恢复路径。
- 独立审阅无未处理 P0/P1；DIA 同步 README、release notes、数据结构与项目记忆；HLG 标准追加交接。

## 风险与后续

- 旧百万行数据库首次启动创建组合索引会增加一次性启动时间和磁盘占用。
- `ORDER BY RANDOM()` 仍为全库随机排序；深页 offset 仍随偏移增长。
- 历史 path 收藏仅在对应文件存在时迁移为 ID，缺失后重新入库的极端兼容场景需后续专项处理。
- 瀑布流尚未窗口化，持续滚动数千项后的 DOM 与内存增长需单独量化并迁移。
- 非零 offset 直接越界或分页期间数据大幅缩减时，当前 `totalExact` 仍可能把 offset 下界误标为精确值，需后续修正边界契约。
- SQLite `LIKE` 的 ASCII 大小写语义与已删除管理员旧 JWT 的角色存续是 HEAD 既有安全风险，应独立修复；若后续发布同时扩大公网或多租户暴露面，必须提升为发布门禁。
