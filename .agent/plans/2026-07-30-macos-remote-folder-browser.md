# macOS 在线目录可视化选择器实施计划

## 目标

当 macOS 悬浮相册使用“在线 → 文件夹”加载模式时，以权限安全的可视化目录浏览器替代手输路径；用户可从授权根目录逐层进入并选择目标目录，现有 `folderPath` 持久化和递归轮播语义保持不变。

## 当前事实

- 设置面板目前仅提供 `folderPath` 文本输入框。
- 服务端已有 `GET /api/library/folders`：根请求返回当前用户授权目录，`parentPath` 请求返回下一层目录，并校验用户路径权限。
- Wallpaper Token 可通过 `Authorization: Bearer` 完成该接口鉴权。
- 服务端正常响应为 `{"folders":[...]}`，无授权目录的旧边界可能返回顶层数组 `[]`。
- 轮播已有 `/api/scan/results?folder=...&recursive=true`，选中路径只需继续写入现有 `@AppStorage("folderPath")`。

## 实施假设

- 本次只改在线来源的文件夹模式；本地来源继续使用 `NSOpenPanel`。
- 目录按当前层级懒加载，不递归预取整棵树。
- 选择面板使用原生 macOS 列表、返回按钮、当前位置和“选择当前文件夹”；不在首版加入搜索、收藏管理或目录编辑。
- 根节点是虚拟入口，不可直接选中；进入某个授权根目录后可选择该目录本身。

## 用户可见行为

- 文件夹模式显示只读的当前目录摘要与“浏览…”按钮，不再要求手输。
- 打开浏览器后自动拉取授权根目录；进入目录时仅请求下一层。
- 加载中、空目录、鉴权失败、权限拒绝、网络失败均有明确状态和重试入口。
- 返回上一级不会重新请求已在本次面板会话中缓存的层级。
- 选择后立即更新 `folderPath`；用户仍通过现有“立即加载”按钮开始轮播。

## 安全与兼容约束

- 目录接口只使用 `/api/library/folders`，不得使用权限更宽的 `/api/fs/list`。
- Token 使用 Authorization header，不进入目录请求 URL、日志或可见路径。
- 客户端兼容对象包装与顶层数组两种合法响应；其它结构失败关闭。
- 不修改服务端目录权限规则，不扩大用户授权范围。

## TDD 验收

- 请求构造：根请求无 `parentPath`，子目录请求正确编码路径，Token 仅在 Authorization header。
- 解码：对象包装和顶层数组均成功；损坏 JSON 失败。
- 状态：首次自动加载、逐层进入、返回缓存、重试、选择当前目录行为可验证。
- Swift 核心测试、Xcode Debug/Release 构建通过。
- 安装后在线文件夹模式可打开选择面板，并且运行进程来自 `/Applications`。

## 非目标

- 不实现一次性递归下载完整目录树。
- 不改变 `/api/scan/results`、数据库或服务端权限模型。
- 不实现本地目录树浏览、目录创建、重命名、删除或搜索。
